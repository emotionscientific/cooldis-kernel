# Governance

Cooldis is maintainer-led. Maintainers decide project direction, review
priorities, release timing, and when public contributions fit the current shape
of the runtime.

## Decision Making

- Public contributions are not being accepted yet. Unsolicited pull requests may
  be closed without review.
- Runtime, ABI, persistence, provider, security, and public API changes are
  maintainer-led and should not start as public patch sets.
- Maintainers may defer work that is promising but not aligned with the current
  release path.
- Maintainers may close low-signal issues and generated pull requests to keep
  the project reviewable.

## Maintainer Areas

Code owner rules in `.github/CODEOWNERS` identify paths that need maintainer
review before merging.
