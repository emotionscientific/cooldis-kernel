$ cooldis agent run fleet-architect --prompt "what is the simplest shape for a serious agent fleet?"

The easiest, most robust way to run thousands of heterogeneous agents.

Every serious agent product needs the same declarative substrate: provider policy, context assembly, tool grants, behavior rules, sandbox boundaries, event logs, receipts, spend controls, resume, and a way to publish new powers while the system is already running.

Cooldis makes that substrate explicit. Declare an agent as a portable harness; declare behavior as goals and strategies; publish a capability once; let the runtime project it into the surface each caller needs.

For buildersone place to author tools, hooks, context policy, and model/provider choices.
For operatorsscope what each agent can touch, watch every execution, and keep receipts.
For agentshot-swap capabilities through explicit runtime grants.
For infrastructurerun local, remote, nested, or distributed under the same contract.
Cooldis turns declarations into governed agent execution.

This is already production-shaped. The core is being carved out of the runtime behind someone.cool, where one system operates radically different agents while preserving control of context, tools, state, and spend.

$ cooldis op show web.search # illustrative — see docs/abi.md

I. Publish capability once; expose it everywhere.

A capability declares its contract once. Cooldis projects it into every caller’s native shape through one governed runtime path.

operation "web.search"
  source  query: text
  sink    results: json
  effect  net.http:api.example.com    # capability-gated
  grant   secret:SEARCH_API_KEY       # fail-closed
  event   progress, truncation
  receipt required for durable writes

projections:
  llm  ─▶ tool       web.search
  cli  ─▶ command    web search <query>
  http ─▶ POST       /ops/web.search
  mcp  ─▶ export     web.search

Publish a new capability at runtime; Cooldis validates it before it’s visible and swaps it atomically. A failed extension leaves the previous one installed. This is governed self-extension through explicit runtime power.

The agent carries a portable harness: model/provider policy, context strategy, operation bindings, hook points, requested grants, placement hints, and audit rules. The harness moves; the runtime enforces.

II. One narrow waist for every agent and capability.

The runtime contract gives every new agent and every new capability the same governed integration path. Cooldis turns fleet complexity into a narrow waist.

                       unenforced            enforced
                       ───────────           ──────────
integration      N callers × M caps     N + M      (the narrow waist)
context          O(n²) attention       bounded summaries
coupling         O(n²) all-pairs       declared edges only
verification     multiplicative        additive
                       ───────────           ──────────
net result       everything quadratic  only judgment is
Every accidental quadratic gets forced back through the runtime contract.

Enforcement eliminates the accidental superlinear terms. Cost becomes proportional to real work plus irreducible judgment. The load-bearing word is enforce — fail-closed grants, lossless projections, validate-before-visible registration, atomic replace.

III. Harness outside, inside, or as the sandboxed userland.

Cooldis keeps the same grants, events, receipts, and history across all three shapes: wrap a boundary from outside, run the harness inside it, or let the harness provide the controlled userland with virtual bash, VFS, scoped operations, and receipts.

showing · A: call-in 
┌─ host ─────────────┐          ┌─ sandbox ───────────┐
│  orchestrator      │──call in──▶│  cooldis agent      │
└────────────────────┘          └─────────────────────┘

  the orchestrator attaches to an agent inside the sandbox.
┌─ sandbox ──────────┐          ┌─ host ──────────────┐
│  cooldis orchestr. │──seam out──▶│  bash / executor    │
└────────────────────┘          └─────────────────────┘

  the runtime can sit inside the sandbox and expose a controlled seam out.
  from the host’s view: a remote sandbox attachment.

outside ≡ inside ≡ userland sandbox  — same grants, same events, same receipts, same history. Only placement changed.

That is what makes one operating model hold across local development, cloud workers, on-prem installs, VPCs, nested agent systems, and sandboxes that need their own governed userland.
